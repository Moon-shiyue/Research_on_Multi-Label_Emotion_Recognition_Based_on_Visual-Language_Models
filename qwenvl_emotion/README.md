## 1. 探索动机

项目启动初期，围绕「如何让视觉语言模型适配多标记情感识别」这一问题，
团队调研了两条技术路线：

| 路线 | 代表方案 | 核心思路 |
|------|---------|---------|
| **A. 参数高效适配** | CLIP + 手工模块 | 冻结预训练主干，通过架构设计与少量适配参数完成任务 |
| **B. 原生模型微调** | Qwen2.5-VL + LoRA | 直接微调通用多模态大模型，靠其内部能力完成融合与推理 |

本目录是路线 B 的探索实现（模型封装、Prompt 策略设计、LoRA 训练脚本）。

## 2. 两条路线的技术对比

```
┌─────────────────────────────────────────────────────────────────┐
│                    路线 A：CLIP + 手工模块                        │
│                                                                  │
│   Image ──→ ViT-B/32 ──→ 512d ──┐                               │
│                                   ├──→ 冲突感知融合 ──→ 环形分类头 │
│   Text ──→ CLIP Text ──→ 512d ──┘    (模块①)         (模块②)     │
│                                                                  │
│   特点：模块化、可解释、每步可控                                   │
│   参数：总 169M，可训练 18.9M（VL-Adapter 占主干 4.57%）           │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    路线 B：Qwen-VL LoRA 微调                      │
│                                                                  │
│   Image ──┐                                                      │
│            ├──→ Qwen2.5-VL-3B (LoRA) ──→ JSON {"joy":0.9,...}   │
│   Prompt ─┘    (模型内部自动编码+融合+推理)                        │
│                                                                  │
│   特点：简洁、情感语义强、仅需设计 Prompt                          │
│   参数：~3B 总量，LoRA ~60M 可训练（约 2%）                        │
└─────────────────────────────────────────────────────────────────┘
```

| 维度 | 路线 A（CLIP） | 路线 B（Qwen-VL） |
|------|---------------|------------------|
| 模型类型 | 双塔编码器（需设计融合） | 原生多模态大模型 |
| 融合方式 | 显式注意力模块，可查看注意力分布 | 模型内部 Transformer 隐式完成 |
| 标签关联 | 显式先验矩阵，可解释 | 依赖模型内部知识 |
| 可训练参数 | 18.9M（4.57%） | ~60M（约 2%） |
| 训练方式 | 判别式（BCE / 非对称损失） | 生成式（Next Token Prediction） |
| 输出形式 | sigmoid 逐标签置信度（天然多标记） | JSON 文本（需解析 + 阈值化） |
| 显存需求 | ~8GB | ~16GB |
| 额外权重下载 | CLIP ViT-B/32（约 600MB） | Qwen2.5-VL-3B（约 6-7GB） |
| 推理速度 | ~50ms/图 (V100) | ~200ms/图 (V100) |

## 3. 选型结论

经过调研与预实验，项目最终采用**路线 A（CLIP + 核心模块）**，依据如下：

**① 与「研究内容」技术方案一致**
项目三大核心模块均以 CLIP 为基座设计：模块① 在双塔特征上做冲突感知融合，
模块② 在 CLIP 统一语义空间上构建情感环形分类头，模块③ 在 CLIP 双塔各层插入
适配器。路线 B 与这一方案不兼容。

**② 多标记输出更直接**
路线 A 用 sigmoid 逐标签输出置信度，天然适配「一张图多个情感共存」的任务；
路线 B 需要模型生成 JSON 文本再解析，标签数固定时反而增加了不确定性
（需处理解析失败、格式偏差等情况）。

**③ 指标与标签体系已对齐**
路线 A 已对接 8 类 Mikels 基础情感标签体系、渐进式环形损失、KL/Cosine 等
分布学习指标；切换到路线 B 需要重新设计整套评估流程。

**④ 可解释性分析更可控**
项目第四阶段需要做 Grad-CAM++ 热力图与模态贡献度量化。路线 A 的注意力模块
可直接输出每个情感标签对图像区域的关注分布（`attention_maps`），
路线 B 的解释需要依赖额外的归因方法。

**⑤ 算力与工程成本**
路线 A 显存需求约 8GB、依赖已缓存；路线 B 需 16GB 显存并下载 6-7GB 权重，
在项目算力预算下，把资源集中在路线 A 的多轮对比实验与消融实验上更划算。

## 4. 本目录代码构成

虽然未纳入最终方案，以下实现仍有参考价值：

| 文件 | 内容 | 参考价值 |
|------|------|---------|
| `config.py` | 三种 Prompt 模板（Direct / CoT / Contrastive）+ 中文情感映射 | Prompt 设计的备选思路 |
| `model.py` | Qwen2.5-VL 封装 + LoRA 注入 + JSON 输出解析 | 生成式情感识别的实现范式 |
| `train.py` | 生成式训练循环（梯度累积、余弦调度、早停） | 训练框架参考 |
| `dataset.py` | 图文数据加载（输出 PIL 图像供 processor 使用） | 数据处理参考 |
| `utils.py` | 与主方案统一的评估指标 | 指标一致性 |
| `verify.py` | 配置与 Prompt 校验（无需 GPU） | 已通过验证 |

## 5. 运行方式

```bash
cd qwenvl_emotion

# 配置验证（无需 GPU，可直接运行）
python verify.py

# 完整微调（需要 GPU + 下载 Qwen2.5-VL-3B 权重，约 16GB 显存）
python -m qwenvl_emotion.train --data_root ./data --epochs 5 --prompt_strategy cot
# 显存不足时可开启 4bit 量化：
python -m qwenvl_emotion.train --data_root ./data --epochs 5 --load_in_4bit
```
